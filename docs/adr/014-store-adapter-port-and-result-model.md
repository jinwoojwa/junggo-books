# ADR-014 StoreAdapter 포트는 매물 목록을 돌려주고, 조회 결과 상태는 StoreResult로 분리한다

- 상태: 제안
- 날짜: 2026-10-30

## 맥락

ADR-005가 서점별 `StoreAdapter`를 `List<StoreAdapter>`로 병렬 실행하기로 했지만, 인터페이스와 공통 모델은 정하지 않았다. 알라딘(B07)과 YES24(B08) 어댑터, 가격 비교 서비스(B09), 캐시(B10), 로그(B13), 최저가 기록(B12)이 모두 이 모델에 기대므로 구현 전에 정해야 한다.

이미 정해진 것이 있다.

- 서점 식별자는 `ALADIN`, `YES24`다. `store_fetch_log`와 `daily_lowest_price`의 CHECK 제약이 강제한다.
- 서점 조회 결과 상태는 `OK`, `EMPTY`, `TIMEOUT`, `FAILED`, `PARSE_ERROR`, `BLOCKED`다(`store_fetch_log.status`).
- 매물 상태 등급은 `BEST`, `GOOD`, `FAIR`, `POOR`, `UNKNOWN`이다(`daily_lowest_price.condition`).
- 포트는 `price.application.port.out`, 도메인 모델은 `price.domain`에 둔다(ADR-012).

두 서점의 중고 상태 등급 체계도 다르다.

| 공통 등급 | YES24 | 알라딘 |
| --- | --- | --- |
| `BEST` | 최상 | 최상 |
| `GOOD` | 상 | 상 |
| `FAIR` | 중 | 중 |
| `POOR` | 하 | 없음 |

알라딘의 "매입 불가"는 알라딘이 매입하지 않는 책이라 판매 목록에 나올 수 없으므로 등급이 아니다. 또 `FAILED`, `TIMEOUT` 같은 조회 결과 상태는 매물의 속성이 아니다. 매물은 조회가 성공했을 때만 존재한다.

## 결정

### 모델

`price.domain`에 둔다. 이름은 구현 때 확정한다.

- `Store`: `ALADIN`, `YES24`.
- `Condition`: `BEST`, `GOOD`, `FAIR`, `POOR`, `UNKNOWN`.
- `Offer`: 실제로 존재하는 매물 하나. 가격(원, `int`), 배송비(원, `int`), `Condition`, 서점 원문 상태 라벨, 상품 링크를 갖는다. 조회 상태 필드는 없다. 총액은 값을 따로 들지 않고 `price + shippingFee`로 계산한다.
- `StoreResult`: 서점 조회 한 번의 결과. sealed 타입이다.
  - `Found(store, offers, latency)`: 상태 `OK`. 매물이 하나 이상 있다.
  - `NotFound(store, status, latency)`: 상태는 `EMPTY`, `TIMEOUT`, `FAILED`, `PARSE_ERROR`, `BLOCKED` 중 하나. 매물이 없다.
  - 둘 다 `status()`를 가진다. 매물은 `OK`일 때만 존재한다는 규칙이 타입으로 표현된다.

### 포트

`price.application.port.out`에 둔다.

- `StoreAdapter`는 `Store store()`와 `List<Offer> fetch(Isbn13)`를 갖는다. 입력은 `Isbn13`만 받는다. `price`는 `book`의 `domain`만 쓸 수 있고(ADR-012), 서점 검색은 ISBN으로 한다.
- 어댑터는 조회에 성공하면 매물 목록을 돌려준다. 매물이 없으면 빈 목록이다.
- 실패는 `StoreFetchException`(상태를 담는다)으로 던진다. 어댑터는 `StoreResult`를 만들지 않는다.
- 가격 비교 서비스(B09)가 어댑터 호출을 감싸 `StoreResult`로 바꾼다. 빈 목록은 `NotFound(EMPTY)`, `StoreFetchException`은 그 상태, 타임아웃은 `TIMEOUT`, 그 밖의 예외는 `FAILED`가 된다. 소요 시간도 서비스가 잰다.
- 서비스는 `List<StoreAdapter>`를 `store()` 기준 `Map`으로 다룬다. 캐시 키 `{isbn13}:{store}`(ADR-007)를 만드는 데도 쓴다.

### 상태 등급 정규화

- 서점 표기를 `Condition`으로 바꾸는 일은 각 서점 파서가 한다. 공통 모델은 서점의 표기를 모른다. 매핑은 이름을 그대로 서수로 옮긴다(최상 → `BEST`, 상 → `GOOD`, 중 → `FAIR`, 하 → `POOR`). 알라딘에는 `POOR`가 없다.
- 서점 원문 라벨은 `Offer`에 보존하되 DB에는 저장하지 않는다. 응답과 화면에서 "서점 기준" 안내에 쓴다. 두 서점의 같은 이름 등급이 정확히 같은 기준이 아니라는 안내는 FE02에서 문구로 처리한다. 도메인은 서점별로 등급을 다르게 다루지 않는다.
- 등급을 매핑하지 못한 매물은 버리지 않고 `UNKNOWN`으로 두고 경고 로그를 남긴다. 가격과 링크는 유효해서 비교에 쓸 수 있고, 서점이 새 등급을 추가했을 때 로그로 알아챌 수 있다.

### 파싱 실패의 범위

- 매물 한 행을 파싱하지 못하면 그 행만 건너뛰고 경고 로그를 남긴다.
- 기대한 영역(매물 목록 컨테이너)이 없는 등 페이지 구조가 바뀐 경우만 `PARSE_ERROR`다.
- `BLOCKED`는 서점이 차단했을 때만 쓴다. 우리 쪽 요청 제한(B14)과 별개다.

### 책임 경계

- 가져오기와 파싱의 분리(ADR-005)는 어댑터 내부 구조로 둔다. 공통 파서 인터페이스는 만들지 않고, 서점이 둘이 된 뒤(B08)에 중복이 보이면 추출한다.
- 타임아웃은 이중으로 둔다. 어댑터는 HTTP 클라이언트 타임아웃을 설정하고, 서비스는 전체 상한을 건다. 그래서 포트 시그니처에 타임아웃이 없다. 구체적인 값과 가상 스레드 사용 여부는 B09에서 정한다.
- 서점별 최소 요청 간격은 B14에서 다루며 이 포트에 넣지 않는다.
- `Store`의 한글 표시 이름은 도메인이 아니라 표현 계층에서 매핑한다.

### 수집 범위와 채널

- 알라딘은 이 광활한 우주점(오프라인 매장 재고를 온라인에서 구매)만 조회한다. 알라딘 오프라인 중고 매장의 재고는 직접 방문해 사야 해서 배송비 포함 총액을 같은 기준으로 비교할 수 없으므로 제외한다.
- 이 범위에서는 서점이 정해지면 판매 경로도 정해지므로 `Offer`에 채널 필드를 두지 않는다. `daily_lowest_price.channel`(`VARCHAR(30)`, NULL 허용)은 기존 마이그레이션을 고치지 않고 NULL로 둔다. 한 서점에 판매 경로가 둘 이상 생기면(예: YES24 마켓플레이스 판매자 매물) 그때 필드를 추가한다.

### 아직 정하지 않은 것

- 주문 금액에 따라 달라지는 배송비(무료 배송 기준)를 어떻게 계산할지. 단건 기준 배송비를 쓰는 것을 기본으로 하되, 서점 수집 설계서와 맞춘다.

## 대안

- 어댑터가 `StoreResult`를 직접 돌려준다. 어댑터마다 상태 변환, 지연 시간 측정, 예외 처리를 반복하고, 어댑터를 쓰는 쪽에서 타임아웃을 일관되게 걸기 어렵다.
- 예외만 던지고 빈 결과는 구분하지 않는다. `EMPTY`와 실패는 캐시 TTL(3시간, 10분)과 화면 표시가 다르다.
- `Offer`가 조회 상태를 들고 있다. 실패한 조회에는 매물이 없어 의미 없는 필드가 생기고, 매물이 있는데 상태가 실패인 불가능한 조합이 가능해진다.
- `StoreResult`를 단일 클래스로 두고 생성자에서 검증한다. 단순하지만 규칙이 런타임 검증으로 남는다.
- 서점마다 등급 enum을 따로 둔다. 서점이 둘뿐인 지금은 비교와 `daily_lowest_price` 저장에서 변환이 늘어나기만 한다.
- 공통 `Parser` 인터페이스를 먼저 만든다. 서점이 하나일 때 만들면 추상화가 알라딘에 맞춰진다.

## 결과

서점 추가는 `StoreAdapter` 구현 하나로 끝나고, 한 서점의 실패는 `NotFound`로 격리되어 다른 서점 결과에 영향이 없다. 조회 상태가 `StoreResult`에만 있어 로그(B13), 캐시(B10), 최저가 기록(B12, `Found`일 때만)이 같은 모델을 쓴다.

대신 서비스가 어댑터 호출을 감싸는 코드를 책임지고, 어댑터는 실패를 예외로 구분해 던질 의무가 있다. 서점 표기를 서수로만 옮기는 매핑은 두 서점의 기준 차이를 흡수하지 못한다. 그 차이가 가격 비교 판단에 영향을 줄 만큼 크다고 확인되면 등급을 서점별로 나누거나 비교 대상에서 제외하는 방안을 다시 본다. 서점별 입력이 ISBN13만으로 부족한 서점이 생기면 포트의 입력 타입을 다시 본다.
